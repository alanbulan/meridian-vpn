# Linux 字段与功能落地清单

更新：2026-11-03。此页更新全页审计的基线状态；完整原版字段、官方页码及未实现项保留在 [约70项全页面审计](reference/UNIVPN-FEATURE-AUDIT.md)。参考为联软官方20260903文档；用户精确版本与企业网关尚未确认。

**基础字段与新增能力均在下表列出；验证结论分别注明真实认证、受控测试和未执行的实网验收。**

**字段出现、被保存、被后端消费、被测试是四件事。** 以下不把表单存在等同于协议互通，也不把 OpenConnect 的同名功能当成联软专有实现。

## 原归档验证范围（不代表本轮重新执行）

- 实际运行：MyGo Linux原生窗口、配置/搜索/主题/语言流程。
- 实际认证：官方Debian OpenConnect 9.12，受信本地TLS认证成功、错密码拒绝、不信任TLS拒绝、取消；直接覆盖生产认证解析器，零CONNECT。
- 受控测试：NM创建/激活/失败/清理、真实子进程超限/取消、接口计数读取、参数及持久化安全。
- 未执行：真实TUN、企业内网资源、DNS/路由修改及恢复、专有网关互通。没有声称Linux完整VPN端到端已通过。

## 登录启动与断线恢复补齐

- A79开机启动：`internal/autostart`管理唯一用户级`meridian-vpn.desktop`；UI显示目标/可执行文件后再次确认。只启动应用，不传配置/秘密参数，不自动连接。Linux目录与文件所有者、符号链接、外部文件冲突、Desktop Entry转义均验证；隔离临时目录测试，不修改实际宿主启动项。
- 断线恢复：Settings.ReauthOnLoss可选；仅曾Connected且失败后的清理已确认时，延迟5秒提示一次新认证。主动断开/清理未知不提示，取消不重复，凭据不缓存或重放。这个功能明确叫“断线后提醒重新认证”，不是自动重连/链路备份。

## 恢复后新增实现（2026-11-03）

- L2TP/IPsec：原生协议编辑器与密码/PSK表单接入Linux NetworkManager-l2tp后端；PPP PAP/CHAP/MSCHAPv2、域、远端ID、单个IKE/ESP提案、强制封装、MRU/MTU均有类型化验证和消费。临时配置、秘密管道、激活/接口验证与回滚接受受控测试，未实际协商IKE/PPP或修改路由/DNS。
- INI：原生只读预览与CLI结构检查仅报告节/字段/疑似凭据字段数量；拒绝重复、无效、过大输入。不会读取出值给用户、导入私有字段、猜协议或执行内容，疑似凭据计数不保证检测所有秘密。
- PKCS#12/PKCS#11：格式选择、引用持久化和认证输入通道已接线；PKCS#12另已通过真实OpenConnect本地mTLS夹具（零CONNECT），但不等于企业网关或硬件兼容。详见CERTIFICATE-AUTHENTICATION.md。
- 实验性联软原生TLS传输已恢复并通过9项本地模拟测试，涵盖持续双TLS/IPv4及静默/分片超时；broker已有凭据校验IPC、进程生命周期及路由/DNS控制器代码，但可信hook会话来源、后代进程隔离和独占网络命名空间租约仍缺失，未实网验收。GUI可选UniVPN并编辑密码认证相关配置，但默认无可信broker配置，连接不可用；拒绝代理、证书与MFA而不静默忽略。国密/QUIC、原生协议MFA/客户端证书/IPv6仍未实现，不列为完成或实测兼容。
